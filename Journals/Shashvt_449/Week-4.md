# Week 4 – UML Diagrams

## Objectives

The main objective of this week was to analyze the functional requirements and system interactions of the project and represent them using UML diagrams.

## Activities Completed

- Analyzed the major functionalities and workflows of the project.
- Identified the actors involved in the system.
- Identified the interactions between users and different system functionalities.
- Created the Use Case Diagram for the project.
- Created the Sequence Diagram for the project.
- Reviewed the diagrams to ensure that they correctly represented the planned system functionality.

## Use Case Diagram

The Use Case Diagram was created to represent the functional requirements of the system and the interactions between the users and the system.

The major use cases identified for the project include:

- User Login
- User Authentication
- Access Notes
- Access Previous Year Questions (PYQs)
- Create Class
- Join Class
- Access Classroom
- Other functionalities provided by the platform

The diagram helps to provide an overall view of what different users can perform within the system.

### Purpose of the Use Case Diagram

The Use Case Diagram helps in:

- Identifying the different actors of the system.
- Understanding the functionalities provided by the system.
- Representing the relationship between actors and use cases.
- Providing a clear overview of the functional requirements.
- Supporting further system design and development.

## Sequence Diagram

A Sequence Diagram was created to represent the flow of interactions between the user and the different components of the system.

The diagram represents how a request is processed step-by-step and shows the order in which different components interact with each other.

For example, during a login operation, the sequence can be represented as:

1. The user enters login credentials.
2. The login form sends the entered information for validation.
3. The system validates the provided information.
4. The system processes the authentication request.
5. The appropriate response is returned to the user.

### Purpose of the Sequence Diagram

The Sequence Diagram helps in:

- Understanding the sequence of events in a particular functionality.
- Representing communication between different components.
- Showing the order in which operations take place.
- Understanding how user requests are processed.
- Supporting the design of the backend and frontend interaction.
