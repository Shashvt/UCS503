# Week 2 -- Requirements Analysis, Module Planning and Project Proposal

## Objective

The objective of this week was to convert the initial project idea into
a more structured set of requirements and modules and use this
understanding while preparing the Project Proposal.

## Activities Completed

-   Discussed the functional requirements of the proposed platform.
-   Identified the major modules and divided the overall system into
    manageable functional areas.
-   Discussed the expected interaction of users with different modules.
-   Planned the basic flow of the major features.
-   Discussed Login and authentication as an entry point to the system.
-   Planned the Notes, Classroom, PYQs, Create Class, and Join Class
    modules.
-   Compared the project requirements from both a functional and
    object-oriented point of view.
-   Started organizing the identified requirements so that they could
    later be represented using UML models.
-   Worked on the Project Proposal using the finalized problem,
    objectives, modules, and planned functionality.
-   Reviewed and completed the Project Proposal for submission.

## Requirements and Module Planning

The major functional areas identified during planning were:

### 1. Authentication

The system should provide a login mechanism through which users can
access the platform.

### 2. Notes

The platform should provide a dedicated section for accessing academic
notes.

### 3. PYQs

Users should be able to access Previous Year Questions for academic
preparation.

### 4. Classroom

The classroom module was planned to support classroom-related
activities.

### 5. Create Class

The system should provide functionality for creating a class.

### 6. Join Class

The system should provide functionality for joining an existing class.

The modules were discussed as interconnected parts of one platform
rather than independent features.

## Requirements Engineering Concepts Applied

The work was related to the Software Engineering syllabus topics of:

-   Problem analysis
-   Requirement elicitation
-   Requirement validation
-   Structured analysis and object-oriented analysis
-   Requirements modelling using UML
-   Software Requirement Specification (SRS)

The identified requirements were reviewed with the team so that the
proposed features remained consistent with the project objective.
