# Week 4 -- UML Modelling: Use Case, Activity, Swimlane and Collaboration Diagrams

## Objective

The objective of this week was to model the project's requirements,
workflows, and interactions using UML diagrams. The diagrams were
prepared from the modules and requirements identified during the
previous weeks.

## Activities Completed

-   Reviewed the project's functional requirements and module structure.
-   Identified the users/actors involved in the proposed system.
-   Studied the interaction between users and system functions.
-   Prepared the **Use Case Diagram template** for the project.
-   Created the **Activity Diagram** to represent the workflow of system
    activities.
-   Created a **Swimlane Diagram** to separate activities according to
    the responsible actor or part of the system.
-   Created the **Collaboration Diagram** to represent communication
    between participating objects/components.
-   Compared the diagrams with the previously identified requirements.
-   Reviewed the diagrams for consistency and completeness.

## Use Case Diagram Template

A Use Case Diagram template was prepared to organize the functional
requirements of the project.

The template considered major functions such as:

-   Login
-   Authentication
-   Access Notes
-   Access PYQs
-   Access Classroom
-   Create Class
-   Join Class

The purpose of preparing the template was to establish the actors,
system functions, and relationships before finalizing the UML
representation.

## Activity Diagram

The Activity Diagram was used to represent the sequence of activities
involved in a system process.

The modelling included:

-   Starting and ending points.
-   User activities.
-   System activities.
-   Sequential flow.
-   Decision points.
-   Alternative paths.

This provided a behavioural view of how a process moves from one
activity to another.

## Swimlane Diagram

A Swimlane Diagram was also created to make responsibilities clearer
within the workflow.

The process was divided into lanes according to the responsible
participant or system component. This made it easier to identify:

-   Which actor performs an activity.
-   Which activity is handled by the system.
-   Where control passes from one participant to another.
-   How responsibilities are distributed throughout the workflow.

The Swimlane representation helped connect the activity flow with the
responsibility of each participant.

## Collaboration Diagram

The Collaboration Diagram was created to represent interactions among
the objects/components involved in a system operation.

It focused on:

-   Participating objects.
-   Communication between objects.
-   Messages exchanged during an operation.
-   The order of interactions.

This provided an interaction-oriented view of the system in addition to
the activity-oriented view provided by the Activity Diagram.
