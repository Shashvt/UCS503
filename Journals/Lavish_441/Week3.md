# Week 3 -- Interface Development, Validation and Verification

## Objective

The objective of this week was to contribute to the initial
implementation of the project interface and ensure that the Login form
handled user input correctly.

## Activities Completed

-   Worked with the team during the initial frontend development.
-   Examined the Login interface and its required input fields.
-   Implemented client-side validation using JavaScript.
-   Added checks to prevent incomplete form submission.
-   Handled invalid input through validation feedback.
-   Tested the Login form with multiple input conditions.
-   Checked the behaviour of the form after applying the validation
    logic.
-   Reviewed the implementation from a verification and usability
    perspective.

## Login Form Work

The Login page was selected for validation because it acts as an
important entry point to the platform.

The JavaScript validation checks included:

-   Whether required fields were empty.
-   Whether the entered information satisfied the defined validation
    conditions.
-   Whether invalid input generated appropriate feedback.
-   Whether valid input was allowed to continue.

## Verification and Testing

I tested the validation behaviour using different scenarios:

1.  Both required fields left empty.
2.  One required field completed and another left empty.
3.  Incorrect or invalid input.
4.  Correct and complete input.

The purpose was to verify that the implemented validation behaved
consistently for different user inputs.

## My Contribution

My individual contribution was the JavaScript validation of the Login
form. I worked on the input checks, validation conditions, feedback
behaviour, and basic testing.

## Software Engineering Concepts

This work gave practical exposure to:

-   Software verification and validation.
-   Interface-level design.
-   Input validation.
-   Error handling.
-   Basic testing.
-   Maintainable implementation practices.

It also helped connect the theoretical Software Engineering concepts
with an actual project component.

## Outcome

The Login page received working client-side validation and was tested
against multiple input scenarios. This improved the basic reliability of
the interface and provided a tested component for the continuing project
development.
